description: Audit fsloop on its own run records — where the clock goes, what the critics' filter loses, which bugs no critic raised, whether runs obey the skill — then write a report, a findings file /fsloop can take as its goal, and proposals for /evolve.
argument-hint: "[speed|findings|escapes|conformance] [run id…] [--dry]"
disable-model-invocation: true
---

Measures fsloop from `.claude/fsloop/runs/`, the transcripts and the code. Every audit leaves two files: `report.md`, what was found, and `findings.md`, the standing product defects as a goal the owner sends with `/fsloop`. What concerns fsloop's own configuration becomes `.claude/evolve/inbox/` proposals, since `/evolve` checks invariants and reviews changes together, and fsloop's agents leave `.claude/` alone. A run of this skill changes no fsloop file and no product code; a stale fact it meets is fixed at once per `.claude/rules/evolve.md`.

Arguments: named tracks run alone, none means all four. Run ids narrow the scope, none means every run. `--dry` skips Propose. `<skill>` is this folder's path; `<fsloop>` is the fsloop skill's, `<skill>/../fsloop`, and fsloop's agents are in `~/.claude/agents/fsloop/`.

| Track | Question | `audit.mjs` commands |
| --- | --- | --- |
| [speed](tracks/speed.md) | Where does a run's clock go? | `speed` |
| [findings](tracks/findings.md) | What does the critics' filter drop, and what in it matters? | `funnel`, `lines --recheck 60` |
| [escapes](tracks/escapes.md) | Which bugs did no critic raise, and would a rule have caught them? | `escapes` |
| [conformance](tracks/conformance.md) | Do runs do what fsloop says, and did applied changes work? | `funnel`, `speed` |

1. **Scope.** `node <skill>/audit.mjs runs`, with `--runs <a,b>` when ids were given. It prints the audit folder, each run's state, the snapshot time and the `origin/main` sha, and writes them to `runs.json`. That ref is the local one: `git fetch` has hung here, so the report names the sha. A run not closed stays in scope and is marked partial in every count. Done: the table is printed.
2. **Measure.** The commands of the chosen tracks, each with `--out <audit folder>` and the same `--runs`. Done: each exits 0, and every parse anomaly `lines` prints is read and either harmless or named in the report. Before `findings`, tell the owner its cost from the unlabeled count `lines` prints: about 480k tokens and 25 minutes per 750 items. The ledger keeps labels between audits, so later audits read only new items.
3. **Audit.** One sub-agent per track, in one message: `general-purpose`, `run_in_background: false`. Each prompt names `Repo:`, the paths of `<skill>` and `<fsloop>`, the track file, `<skill>/evidence.md`, the audit folder and the run list, plus the other tracks as out of scope. It carries the question and no suspicion, conclusion or earlier number: an audit handed a hypothesis tends to confirm it. Sub-agents change nothing outside the audit folder. Done: every track returned its report and saved it as `<audit folder>/<track>.md`.
4. **Verify.** Before relaying, check each report yourself: totals sum to their denominators, each conclusion agrees with its own table, tracks that touch the same fact agree, and the two strongest claims hold when you open the code or data they cite. Compare with earlier `report.md` files in `.claude/fsloop/audit/*/` and name what moved. Then commit the tracks' work to the store: `node <skill>/audit.mjs label <audit folder>/labels.json`, `node <skill>/audit.mjs groups <audit folder>/groups-update.md`, `node <skill>/audit.mjs lines --out <audit folder>` with the same `--runs`. A track that produced no such file skips its command. Done: each claim you relay is checked or marked as the auditor's.
5. **Findings file.** `node <skill>/audit.mjs work --out <audit folder>` writes `findings.md` from `groups.md`, with every `defect` group marked `stands`, worst first; `--classes defect,imp+` or `--groups a,b` choose otherwise when the owner asked. Each `missing` line it prints is a path gone from the sha: fix that group's `где:` or its status, then run it again. Read the file once: a finding whose fix turns on a choice only the owner can make gets a `вопрос:` line in its group, and a finding with no clear correct behaviour gets `должно:`. Done: the file exists, no `missing` line is left, and it names the command that sends it.
6. **Propose.** Skipped on `--dry`. One file per observation about fsloop's configuration in `.claude/evolve/inbox/`, in the format of `.claude/rules/evolve.md`. First read the inbox and `.claude/evolve/archive/`: the same idea extends the existing file, and a rejected one returns only with new evidence. `## Evidence` cites run ids, `file:line` and counts with denominators. `## Cost` names the metric, its value now and the direction expected, so the next conformance track can test it. Done: every bottleneck and every class of lost finding has a proposal, a line in `findings.md`, a question for the owner, or a stated reason for none.
7. **Report.** Write `<audit folder>/report.md` for an owner reading it cold, in Russian, in plain words, answer first. Anything still live goes above it: a queued owner message, a held push, a run stuck now. Then: where the time goes; bottlenecks ranked, each with its tag, recoverable range and overlaps; what was cleared; defects that stand and how many went to `findings.md`; questions only the owner can decide; proposals written; what moved since the last audit; what the data cannot show; paths to the tracks' reports. Send the same content in chat. Done: the file exists, and your message ends with the `/fsloop` command `work` printed and the note that `/evolve` applies the proposals.

The owner may edit `findings.md` before sending it: `/fsloop` reads it as the goal, and the file itself tells the run how to read it. The next findings track re-checks every `stands` group, so what a run fixed moves to `fixed` and leaves the next file. The owner regenerates the file any time with `work`.

`node <skill>/audit.mjs` prints its usage; `bun test <skill>` covers it. Labels, root-cause groups and audit folders live in `.claude/fsloop/audit/`, local to this checkout like the run folders.
