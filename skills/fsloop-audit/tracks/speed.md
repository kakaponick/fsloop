# Speed: where does a run's clock go?

Input: `speed.json` in the audit folder, one record per run, oldest first: `clock`, `active`, `idle` in ms; `budget`, active time by what runs at once, its rows summing to `active`; `gaps` over 2 minutes; `limitStops`; `share` by category, with concurrent time split equally; `concurrency`; `stages` with clock and busy time, `open` on one still in progress; `build` (units) and `rework` (review, fix, verdict, assess, integrate); implement `lanes`; launch time per role in `roles`, from the launches the run saved; `generation` per role from all transcripts, with requests, output and thinking tokens and unsplit time. Further raw data: `launches[].transcript` in each `run.json`, `units/*/brief.md`, `journal.md`, `logs/`.

1. **Budget.** One table across runs from `budget`, with clock, active and idle above it. Done: the rows sum to active time.
2. **Idle.** Explain every gap over 10 minutes from the transcripts around it: a limit stop (when it hit, when the limit reset, when work resumed), the owner, a stuck wait, or unknown. Say what could have resumed earlier. Done: each such gap has a cause, or `unknown` with what you checked.
3. **Lanes.** Implement agent-hours against lane clock. For each unit that waited, read its `Blocked by:` and `## Files`: a real dependency or a shared file. Simulate the actual schedule, a higher `K`, and the schedule without shared-file links; each simulation states its assumption about true dependencies. Name the shared files that chain units and check them against `.claude/fsloop/config.md`. Done: each waiting unit is classified, and the simulated actual schedule is compared with the real one.
4. **Rework.** `rework` per hour of `build`. Where it comes from: red commands in `logs/` against critic findings (`funnel.json` when present). Implement time inside Integrate. Done: a share for each source.
5. **Generation.** Tokens per second per role from `generation`, thinking share, tokens per landed line. Whether fast mode appears in the data. Estimate a 10% cut in output, marked INFERRED. Done: a row per role.
6. **Waits.** Finished launches waiting on batch peers (`run_in_background: false`), background completions waited on, installs per lane, and any owner message left queued. Queued messages and T3 state: `~/.t3/userdata/statev2.sqlite`, opened read-only. Done: each kind counted in agent-hours or clock hours, unit named.
7. **T3 and machine, for time steps 1–6 leave unexplained.** Traces at `~/.t3/userdata/logs/server.trace.ndjson*` cover recent hours only; `orchestration_v2_events` is empty after compaction. CPU, disk and antivirus are unmeasured, and a slept machine reads as idle.

Report: the budget table; bottlenecks ranked, each with its loss, recoverable upper bound and realistic value, tag and overlaps; what you cleared, with the number that clears it. Trend: the same metrics per run, oldest first, since fsloop changed between runs.
