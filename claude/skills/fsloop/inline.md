# fsloop — the inline mode

Read when Route picks inline. The run is the worktree mode with one unit, built in the start checkout: no worktree, no lanes. You stay the orchestrator — briefs, launches, journal, no code read. The start checkout is shared with the user and other threads, so the git rules of `CLAUDE.md` govern every git step, and every path in `start-status.txt` is foreign — never staged, reverted or reformatted, never in a manifest. SKILL.md holds in full, `<wt>` and `<lane>` read as the start checkout, except Worktree, Lanes, Strays, Land and the pass-start rebase of step 4; the steps run as below.

**Target** — the branch the run's commits go to: the start checkout's upstream (`git rev-parse --abbrev-ref @{u}`), or `<default>` on a detached HEAD or a branch with none; written `<target>` below, a decision. The start checkout is never switched to another branch, and HEAD never leaves a commit `origin/<target>` lacks.

Of Strays only the snapshot stays: `git status --porcelain` at every launch and every completion. A manifest file changed while no launch of the unit ran is another thread's edit — the unit blocks with that file neither staged nor checked out, a decision.

**Before every pull** (steps 1, 5, 8): another thread may be mid-git in this tree. `.git/rebase-merge`, `.git/rebase-apply`, `.git/MERGE_HEAD` or `.git/index.lock` present → re-check every 30 s for up to 10 min, then report and stop; never `--abort` an operation this run did not start, never delete the lock.

1. **Start.** `git $MJ pull --rebase --autostash origin <target>` — the code is fresh and every local commit stays, replayed on top. A conflict → Resolve; an autostash that does not re-apply stays in `git stash list`, named in the report. `git status --porcelain` into `<run folder>/start-status.txt`. Then `common.md` per SKILL.md → Project facts, the start checkout as both paths.
2. **Map, Spike** — SKILL.md steps 1–2; a spike's doc commits with `u1`.
3. **Brief** — SKILL.md step 3 for one unit `u1`, all six parts. A goal Map or Decompose finds past Route's line switches to the worktree mode under the same run id, a decision.
4. **Implement, Verify** — SKILL.md step 4's Implement and Verify with `Repo:` the start checkout: each session the brief names acquired per `backend.md` → Sessions and named in every launch's prompt; `fsloop-implement` with the brief's path; Verify as a command list; debug as there. The type-check covers the whole shared tree: an error only in a file `start-status.txt` lists, or in one another thread changed since, is not the unit's — recorded with the file, a decision, and the gate judges the unit's own files; no launch edits that file. Block saves `git diff` of the unit's files as a patch, then `git checkout -- <files>` for the files the unit changed, its CREATED files moved into the run folder. A UI part's frames come from the start checkout itself (`ui.md` → The shot server).
5. **Commit** — after Verify of `u1`, and again of `f1`, a command list: `git add` by explicit path — the unit's manifest files it changed, its CREATED and, with `u1`, the spike docs of step 2, none from `start-status.txt`; `git commit -F <message>` (SKILL.md → Commit message); `git $MJ pull --rebase --autostash origin <target>` — a conflict → Resolve, anything pulled → type-check and the unit's tests again.
6. **Review** — SKILL.md step 5 with `Repo:` the start checkout and the run's file list `git log --grep='Fsloop-Run: <run id>' --name-only --format= | sort -u` — `origin/<target>...HEAD` would carry another thread's commits.
7. **Fix** — SKILL.md step 6, the fix list as one unit `f1` through steps 4–5 above, then its craft verdict.
8. **Integrate** — `git $MJ pull --rebase --autostash origin <target>` — a conflict → Resolve; anything pulled → type-check and the units' tests again. Then SKILL.md step 7's checks, run as step 7 runs them. `git log --format='%h %s' origin/<target>..HEAD` is the push list, each commit without the trailer `Fsloop-Run: <run id>` named in the report as another thread's; a critical or major finding still open after Fix holds the push, as SKILL.md step 7 says; `git push origin HEAD:<target>` — or, when `CLAUDE.md` forbids an agent's push there, no push and the report says so; rejected → the pull once more, push; rejected again → reported verbatim, never forced.
9. **Finish** — SKILL.md step 8 — its leftovers include the shot teardown in the start checkout when the run raised a shot database there; every session the journal records as acquired is released.
