# fsloop — the assessed loop

Read at bootstrap when `/fsloop` got `N`; without `N` nothing here runs. After Fix it adds an assessment that decides whether another pass is built; the baseline every run takes at Map (`ui.md` → Baseline) is its count's start.

## Passes

A **pass** is steps 3–6 of SKILL.md, then Assess. The first pass builds the goal; each later pass builds only the gap Assess found and starts at step 3 — Map runs again only for a surface no earlier pass mapped (its production shape and baseline) and Spike only for an unknown the findings name that no doc covers. Weight earns a pass: critical and major findings above the bar open the next one; minors go to candidates — a pass costs five launches, a unit and, per surface, the craft launches of `ui.md`'s table; a minor does not pay for it. The run ends when it **converges** (an assessment with no critical or major above the bar), **stalls** (their count, declined excluded, did not fall against the previous assessment — or every one of them sits on code the previous pass wrote: fixes of fixes are a stall and go to candidates), or after pass `N`. The audit score per surface and any reversal are reported, never stop conditions.

## Craft assessment

The design instrument for a surface the goal makes or reshapes, at each Assess: the baseline's launch (`ui.md` → Baseline) on the surface as the pass left it, the pass's final frame by path and the fix patches since, description `assess<p> craft <surface>`, saved to `<run folder>/craft/assess<p>-<surface>.md`. Its `AUDIT:` scores and its critical and major findings are the surface's count, the same assessment at every stage, so baseline → now compares; a new surface's count starts at the first Assess.

## Assess

After Fix, every lane closed. A craft assessment of each surface the goal makes or reshapes. `fsloop-critic` in assessment mode — `LENS: code assess` always, `LENS: runtime assess` when the run has a backend part — on everything the goal touched: briefed with the goal in the user's words, the spike docs, the production shape of every surface and the full file list of the run; no unit brief, no settled decisions, no prior findings: the built result is judged as a stranger would judge it. The **end-to-end run** — the goal's scenario run for real per The end-to-end run below (a page's task walk is its implementer's tests, not part of this run). Last and alone — every launch done, every shot server stopped — one background command list (SKILL.md → Background commands) with the suite and the whole-repo lint on the run branch, the pass's only whole-suite run; its red lines judged as SKILL.md step 7 says. Judge by the bar, with two differences: a settled decision the assessment overturns is reopened, never dropped; a finding on what no pass of this run built is a candidate. Then decide by the rule of Passes: converged · stalled · next pass (back to step 3 with the findings as the goal) · cap.

Finish adds the assessments table (pass / audit and critique scores and craft critical+major per surface, baseline → now / critical+major, declined excluded / minors to candidates / reversals / outcome) and, in the summary, converged, stalled or cap, at which pass, with the count that decided it, and the audit and critique scores per surface, baseline → now.

## The end-to-end run

The goal's scenario runs for real in `<wt>`: a job enqueued through the service and taken by the worker command (`common.md`) in its dry mode when it has one, against a throwaway database of the run (`<db>_e2e_<run id>` created beside the dev database, the migrate command applied into it, dropped at Finish) — never the shared dev database, whose accounts and jobs another process may hold, and never a live transport from the worker while a live session may be held elsewhere (`backend.md` → Sessions); the row's transitions read back by SQL; a cron's `run` called directly; a client method against the live system where `.spike/` allows — that step goes to a `spike-researcher` with the toolkit, sessions acquired for `<wt>` for the run's duration and released after (no lane is open at Assess). A project with no worker or no database runs the scenario through its own entry point (a CLI, a request to the dev server), the same evidence rule. Each command list's COMMANDS lines become the evidence table (criterion / command / outcome); a step nothing in `.spike/` covers is a decision and `unverified live` in the report. Money — a payment, a paid call, a budget top-up — is never spent by the run: such a step is `unverified live` with the reason, and the report names it for the user.
