---
name: fsloop
description: Turnkey delivery of any size (fix, feature, page, service, worker, cron, migration, stage) from prompt to pushed commit, unsupervised, in any repo. Use on /fsloop, or when asked for a task turnkey / end-to-end / from prompt to commit. Also /fsloop spike, or a request to investigate or reverse-engineer an external system, protocol or format before building on it — research only, no commit.
argument-hint: "[N] [jK] <goal> | init | spike <question> | resume <run id>"
---

A system is judged by what it does when run — a test at a seam, a job through the worker, a call against the live system, the surface on screen at the production shape. A unit is a vertical slice through every layer it needs (schema, migration, service, handler or cron, action or route, page, tests): the UI half and the backend half of one feature are one unit, never two runs. Agents (`.claude/agents/`): `fsloop-implement`, `fsloop-critic`, `fsloop-debug`, `spike-researcher`, `prod-check`, `cold-read`, `fsloop-shots`. Reference files beside this one are read once per run, when first needed: `inline.md` when Route picks the inline mode; `backend.md` at bootstrap, before the first `spike-lease.mjs` call; `ui.md` at Map when any unit will have a UI part; `spike.md` when Map leaves an unknown without a doc, and for `/fsloop spike`; `assess.md` at bootstrap when `N` is given; `init.md` for `/fsloop init`. This file, the reference files and the agent definitions are read once and never re-read. Scripts beside this file run under `node`; `fsl.mjs` is the run folder's keeper (Run folder).

You own the goal from prompt to committed units, unsupervised: no decision goes to the user — `AskUserQuestion` and `EnterPlanMode` stay unused except in `/fsloop init`'s design step (`init.md`); what only the user has (a code, money, an account) you or any launch asks by `socket ask` when the skill `ai-socket` is installed, otherwise it is an OPEN line and the step waits for the report. Decide, and record every judgment call (question / decision / why) — the record becomes the report. Autonomy covers code, local state, everything in `.spike/` and the final integration into `origin/<default>`; before an irreversible action beyond that (data deletion, external sends, live keys, production writes, an account outside `.spike/`) stop and report. Production is read-only shape, never a target; a step that needs what `.spike/` lacks builds against the doc, and the report says what to drop in. In both modes you are the orchestrator: you launch, read reports by their final block, decide, write briefs, commit messages and the journal — and read no code: a patch, a diff, an output goes into a brief by path. Every command whose output is evidence — a test, a type-check, a build, a migration, a job through the worker, a live or production read, a git rebase, merge, commit or push — keeps its raw output out of your context: your context is the run's budget. It runs as a command list (`## Command lists`) or inside a launch, per the agents' contracts. Plumbing whose only output is success — `git fetch`, `status`, `diff` to a patch, `worktree add`/`remove`, `branch -D`, `merge --ff-only`, a stray's `apply` and `checkout`, the install, `spike-lease.mjs` — you run yourself where this file places it. Sub-agents write code and probe systems — a fresh agent per launch, briefed in full. Sub-agents leave `CLAUDE.md`, `.claude/` (fsloop-shots' `.claude/fsloop/auth.json` aside) and settings to you: a law change is an inbox proposal you write (`.claude/evolve/inbox/<YYYY-MM-DD>-<slug>.md` — observed, evidence, proposal, cost); a stale fact, yours or a sub-agent's `FACT` line, you fix at once — Edit in the run worktree, its own commit as a command list, a line in the report.

## Parameters

`/fsloop [N] [jK] <goal>` — `N`, an optional leading integer, turns on the assessed loop of `assess.md` and caps its passes; omitted → one pass, no Assess. `jK` caps the lanes open at once; omitted → `j3`; `j1` is serial. Everything after them is the goal; a first word that is neither belongs to the goal. `resume <run id>` as the whole argument → Resume. `init` as the whole argument → `init.md`: the project's config written and verified. `spike <question>` as the first word → a research-only run per `spike.md`: no run id, no worktree, no lanes, no commit — frame, lease, launch, verify, notify, summary.

**Route** — every other run picks its mode before the run id, from the goal and a read-only look at the code and docs it names (Glob/Grep, the doc it cites, `git status --porcelain`); the mode, the count it rests on and why are the journal's first row.

- **inline** — the goal fits one context: fewer than 3 independent units and fewer than 5 pages, no `N`, no explicit `jK`, no file it will touch carries an uncommitted change in the start checkout, and — for a goal with a UI part — no live dev server holds the start checkout: its frames would be judged from code. One unit, built in the start checkout per `inline.md`: the same orchestration with no worktree and no lanes.
- **worktree** — everything else, and a count you cannot settle from the look. The rest of this file describes that mode; `inline.md` names what of it the inline mode keeps.

An inline run whose Map or Decompose finds the goal past the line switches to the worktree mode under the same run id, `common.md` rewritten with the worktree path, a decision; once Implement has started it finishes inline — the work never splits into units mid-way; the size it reached is a decision. A file it then needs that `start-status.txt` lists stays untouched: that part goes to candidates, a decision.

**Run id** — minted once before the first launch: `date -u +%s%N | git hash-object --stdin | cut -c1-8` — the goal stays out of the shell, where a quote or backtick in it breaks or runs the command. It heads the report and every commit's `Fsloop-Run` trailer.

**Commit message** — every commit of the run, written with Write — a unit's to `units/<unit>/commit.txt`, any other to `logs/<stage>-commit.txt` — and passed by `git commit -F`. Three readers: `git log` (Resolve, the next agent, a reviewer), the project's changelog when it builds one from commits, and the run itself, which finds its commits by trailer. Shape (illustrative):

```
feat(images): send junk and repeated generated pictures back for redraw

Images: a broken picture, or one nearly repeating a recent picture of
the channel, is sent back for redraw; a model check of the topic can be
switched on on the same page.

Blank, noisy and near-duplicate pictures reached channels (brief u21).
A perceptual hash over the channel's last pictures catches repeats; a
vision-model gate for every picture was rejected as too costly, so it
stays an opt-in setting.

Fsloop-Run: 8e185ef0
Fsloop-Step: u21 21/28
Fsloop-Pass: 1/2
```

- **Subject and the body** — the project's commit conventions (`CLAUDE.md`); none stated → a conventional commit, imperative, up to 72 characters, the scope the module or surface the commit changes. The why comes from the brief's problem, the defects it lists and the decisions that rejected an alternative; a commit `fsloop-debug` fixed names its CAUSE.
- **The operator paragraph** — first in the body, in the language the product's users read (`CLAUDE.md`; none stated → the body's), only when a user meets the change: the page by its navigation label, then what changed as they meet it, one to three sentences, no paths, code names or run vocabulary. A spike doc, a config fact, a merge or a test-only commit has none.
- **Trailers** — the last paragraph, one `Key: value` per line with no blank line inside, the harness's attribution lines after them, so `git interpret-trailers` and `%(trailers)` parse the block:
  - `Fsloop-Run: <run id>` — every commit; `git log --grep='Fsloop-Run: <run id>'` lists the run.
  - `Fsloop-Step:` — `u<k> <k>/<total>` a unit, `f<k> <k>/<total>` a fix unit, `spikes`, `merge`, `integrate` (a fix at Integrate), `fact` or `init` (the config).
  - `Fsloop-Pass: <p>/<N>` — with `N` only.
  - `Fsloop-Closes: <finding ids>` — a unit whose brief has them, the ids under its `## Closes`.
  - `Fsloop-Unverified: <criterion>` — one per criterion that fell back to offline.

## Command lists

A **command list** is a run of commands with no judgment between them: Verify, a Land batch, the pass-start rebase, a spike-doc commit, Resolve's continue, Integrate's merge and push. You run it yourself in one Bash call, `cd <repo>` first, `<log>` in the run folder — a unit's under `units/<unit>/` (`verify.log`, `land.log`), any other under `logs/` (`logs/p1-baseline-capture.log`, `logs/integrate-checks.log`) —, each command as:

```
<cmd> > <log>.<n> 2>&1; e=$?; p='<pass pattern>'; [ $e -eq 0 ] || p='fail|error'; echo "<n> <label> — exit $e — $(grep -m1 -iE "$p" <log>.<n>)" | tee -a <log>.lines; [ $e -eq 0 ] || exit $e
```

- Every command keeps the tail `[ $e -eq 0 ] || exit $e`: a red check ends the list before a Land's `merge --ff-only`.
- Output goes to the file, never through a pipe into `grep`: grep's early exit kills the command and replaces its exit code.
- `<label>` is a short name with no quote, `$` or backtick (`type-check`, `rebase`): a command's own text inside the echo's double quotes is expanded and run again.
- The printed lines are the list's `COMMANDS` lines; a miss's line is the red line a brief quotes. `<log>.lines` keeps them on disk — on Resume they are the list's report; a `<log>.<n>` with no line was cut mid-command, and the list runs again from it.
- Fits ten minutes → foreground, `timeout: 600000`. The suite, the build, anything under the machine lock, live criteria, the worker → the same template in one background call (Background commands).

## Project facts

The commands come from the project. A project pins them in **`.claude/fsloop/config.md`** — its config file, committed, written and verified by `/fsloop init` (`init.md` → Config), short since every launch carries it; `## Accounts` (the account kit `spike-researcher` reads) and `## Deploy check` (the checks `prod-check` adds) join it when the project has them. When it exists it is read first and what it states is taken as stated, never re-derived — only what it leaves out is. A config whose `Verified:` sha is behind a change to the package manifest or its lockfile (`git diff --quiet <sha> origin/<default> -- <manifest> <lockfile>` fails) is still used, and the report suggests `/fsloop init`; with no config, the report suggests it too. What the config leaves out, or all of it when there is none, comes from the project's `CLAUDE.md`, the rule files it names and its package manifest (`package.json` scripts, `Makefile`, `pyproject.toml`, …). Read them once at bootstrap and fill this table by role; the rest of this file and the agents name a command only by its role (`<type-check>`, `<lint>`, `<unit tests>`), and `common.md` holds the real one:

| role | what it is |
|---|---|
| default | the branch the run integrates into — `git symbolic-ref --short refs/remotes/origin/HEAD`, else `CLAUDE.md` |
| install | the frozen-lockfile install |
| type-check | the whole-repo type check; none (an untyped language) → `—`, a decision |
| lint | the linter over the files changed against `origin/<default>`; only a whole-repo lint → that, run beside the suite |
| test, one file | how one test file runs |
| unit tests | the unit's test files, every test file importing a changed file (found the way `CLAUDE.md` says; none stated → `git grep -l <path without extension> -- '*.test.*'`), and the catalogue guards |
| guards | the tests that go red when a registry grows (kinds, error types, i18n keys, routes) — their files and the catalogs they demand, read from the tests, never recalled; none → `—` |
| suite | the whole test suite — at Integrate when the run is a large task (a new surface or feature, the schema, permissions, ≥3 modules, or as `CLAUDE.md` defines it); at each Assess always when `N` is given |
| build | the production build — Integrate only, once, when build-exercised code changed |
| migrate | generate a migration from the schema, and apply it; migrations run only on throwaway databases — the tests' own, the shot database at its raise, `<db>_e2e_<run id>` — never on a shared dev database another run may hold |
| worker | how the job runner starts, and its dry mode (a fake transport) when it has one |
| machine lock | a wrapper that serialises heavy commands across runs on one machine (`CLAUDE.md`); none → the suite, the build and browser tests still run one at a time across lanes, by you |
| production shape | the skill or doc that reads production read-only (`prod`), when one exists; none → shapes come from the schema and the product's stated volume, a decision |
| shots | the screenshot tooling of `ui.md` → The shot server, when a unit has a UI part |
| find-polluter | `--run` and `--skip` for `find-polluter.mjs` (`debug.md`) when the runner is not bun or some tests need a lock, a live resource or a browser; none → `—` |
| impeccable | `IMPECCABLE_QUESTION_DISABLED=1 <impeccable launcher> <verb>`, cwd in the launch's tree — `context`, `detect --json`, `surface-brief`, `critique-storage`; the launcher sits under the installed `impeccable` skill (`<start>/.claude/skills/impeccable/scripts/impeccable` or `~/.claude/skills/impeccable/scripts/impeccable`) |

Before the first launch write `common.md` into the run folder. Its head is six lines `fsl.mjs` reads — `Run: <run id>`, `Mode: inline|worktree`, `N: <N or —>`, `K: <K>`, `Start: <start checkout>`, `Worktree: <wt, or the start checkout inline>` — `Start:` as `git rev-parse --show-toplevel` prints it — then `## Goal` with the goal verbatim, then `## Project`: the table above, filled · the shared catalogs several units would write and the guard that trips when each grows, plus the unguarded ones: the schema and its migrations folder, any registry the project keeps by hand, the package manifest and its lockfile · the law (below) by absolute path, with its precedence quoted from `law/ui.md` → Precedence, and the strict rules of `CLAUDE.md` and the rule files it names, verbatim by name, each with the law file it refines · the role map, from the config file or the project's UI rules, a role none of them fills marked `—` · the rest of the config file, verbatim · what `.spike/` holds, from its `README.md`, and that a path through a junction (`.spike/toolkits/<topic>/out/`) lands in the main `.spike/` and is free to write · the known flaky files, from the `flaky` verdicts in earlier runs' suite logs under `.claude/fsloop/runs/*/logs/`, and in the run folders of older versions, `.claude/fsloop/*/` (none → none known). A fact the project does not state is a decision, recorded.

**The law** — `<start>/.claude/skills/fsloop/law/`: `code.md` and `tests.md` bind every unit, `ui.md` and `ux.md` every UI part, `table.md` a unit whose `Kind:` carries `+ table`. It is the run's base law, whatever the project keeps; its precedence over and under the project's rule files is `law/ui.md` → Precedence, which `common.md` quotes. Every launch that writes or judges code reads the law files its unit's kind needs, in full, beside the project's rules; a rule is cited by its file and number or name (`ux 1`, `table #10`, `tests 6`, `code` → Idempotent).

## Machinery

**Worktree** — the run never edits the checkout it was started in; that checkout belongs to the user and to other sessions. Before the first launch: `git fetch origin`, then `git worktree add -b fsl/<run id> <repo parent>/fsl/<run id> origin/<default>` — `<repo parent>` always absolute: under `git -C` a relative path lands inside the repo. In it: the install command (some bundlers reject a junction to another checkout's dependencies); the untracked env files — copied from the start checkout, or written from the example env with local values and fresh secrets, third-party keys empty, either way a decision; `node <start>/.claude/skills/fsloop/spike-lease.mjs link <wt>` — a mirror of `.spike/` without `sessions/` (see `backend.md` → Sessions). No migration at bootstrap: tests carry their own database. Tools default to the starting checkout — yours and every launch's (Launch records): pass the path to Glob/Grep, run shell as `cd <path> && …` or `git -C <path>`, treat a path outside it as foreign.

**Lanes** — every unit in flight owns one: `git -C <wt> worktree add -b fsl/<run id>-u<k> <repo parent>/fsl/<run id>-u<k> fsl/<run id>` (`-`, not `/`: `fsl/<run id>` is itself a branch), install, env files copied from `<wt>`, `spike-lease.mjs link <lane>`, `common.md`, `units/u<k>/brief.md` and the `surfaces/*.md` it cites mirrored into `<lane>/.claude/fsloop/runs/<run id>/` at the same paths (untracked, so the lane has none), then `spike-lease.mjs acquire <lane> <session>` for each session the brief names. Open a lane for a **ready** unit (every unit it is blocked by committed) while fewer than `K` are open and no open unit's manifest or CREATED shares a path with its manifest — the key-merged catalogs and the append-only registries excepted (see Merge). Launch every newly opened lane's implement in one message; on each completion advance that unit alone, then open lanes again. `<wt>` receives only landed units and stays clean while lanes are open. Lanes share the machine: the suite, browser tests and the build run one at a time across lanes and runs, under the machine lock. Close, at Land or Block: `spike-lease.mjs unlink <lane>`, then — only after it printed `unlinked` or `nothing linked` and `<lane>/.spike` is gone — `git -C <wt> worktree remove --force <lane>`, `git -C <wt> branch -D fsl/<run id>-u<k>`. A removal over a standing mirror walks its junctions and empties the main `.spike/`: a failed unlink is a blocker — move the real folder it names out of the mirror, unlink again; never `rm -rf` / `Remove-Item -Recurse` a checkout.

A lane buys isolation between units in flight; when one unit at a time is in flight — the run or the fix list has one unit, or `j1` — that unit runs in `<wt>` itself: no lane, install, env or mirror; `spike-lease.mjs acquire <wt> <session>`; its run-folder files are read from the start checkout's run folder; Land commits on `fsl/<run id>` with no rebase and no `merge --ff-only`; Block saves `git -C <wt> diff` of its files as a patch, then `git -C <wt> checkout -- <files>` and its CREATED files moved into `units/<unit>/created/`. A decision, recorded.

**Merge** — the i18n message catalogs (JSON files of keys, listed in `merge.attributes` beside this file) merge by key: two units appending keys to one object conflict line by line. Every `rebase`, `rebase --continue`, `merge` and `pull --rebase` of the run carries `-c core.attributesFile=<start>/.claude/skills/fsloop/merge.attributes -c "merge.fsl-json.driver=node '<start>/.claude/skills/fsloop/json-merge.mjs' %O %A %B %P"` — written `$MJ` below, placed before the subcommand and spelled out in each command: a shell variable splits the quoted driver. The driver keeps each file's layout byte for byte; a key both sides changed differently stops the merge with `<path>: conflicting keys <keys>`, the file valid and holding the upstream value → Resolve. Every other file merges line by line, so two units that write one never have lanes open together — except an append-only registry `CLAUDE.md` names (a route-permission table, a surfaces list), where each unit writes its own lines and Resolve takes both.

**Resolve** — a rebase or merge stopped on a conflict is work: `git status --porcelain` lists the files; a stop whose hunks are additive on both sides → resolve in place, reading only those hunks — the one code you read. Otherwise a fresh `fsloop-implement` with `Repo:`, the files, the driver's `conflicting keys` line when there is one, both sides' intent (the stopped commit's subject and brief, `git log origin/<default> -3 --format=%s -- <file>` for the base's side) and done-criteria: no conflict markers, type-check and the unit's tests green, no git command beyond read. Then a command list: `git add <files>`, `GIT_EDITOR=true git $MJ rebase --continue` (a merge: `git commit --no-edit`); stopped again → the next Resolve; up to 5 per rebase, then `--abort` and report — the branch and worktree stay. Each resolution is a decision.

**Models** — a launch never inherits your model: the agents above carry theirs in frontmatter; every other launch passes `model` explicitly — `sonnet` for reading (Map). Inheriting yours is a spend defect: record it, do not repeat it.

**Background commands** — the suite, the build, anything under the machine lock, live criteria and the worker run as a background command with the maximum timeout (7 200 000 ms): your command list as one Bash call with `run_in_background`, a launch briefed to do the same; the lock wait counts against the limit, and a command killed at the limit leaves its dead pid as the lock holder. Every background command list gets a Monitor that fires when the newest log in its folder has not grown for 15 min; a firing → that log's tail and its processes, then the list again from the cut command.

**Strays** — `git -C <start> status --porcelain` at every launch and every completion; a file changed since the previous snapshot *and* named by an open unit's manifest or CREATED is that unit's stray — `git -C <start> diff -- <file>` to a patch in the unit's folder, `git -C <lane> apply <patch>`, `git -C <start> checkout -- <file>` (untracked → move); named by two open units, the patch is saved, applied to neither, both recorded. A second stray from the same brief → block the unit. Any other change in the starting checkout is the user's: never touched, listed in the report.

**Run folder** — `.claude/fsloop/runs/<run id>/` in the starting checkout: the run's whole state, and what a UI reads to show it. Never staged: `.git/info/exclude` holds `.claude/fsloop/*` and `!.claude/fsloop/config.md` (the installer adds them; missing → add them before the first write). Its layout is fixed — `fsl.mjs` and Resume see nothing kept elsewhere or under another name:

| path | written by | holds |
|---|---|---|
| `common.md` | you, at bootstrap | Project facts, its six head lines and `## Goal` first |
| `journal.md` | you | `\| # \| stage \| question \| decision \| why \| refs \|` — every decision, before the launch that depends on it; `refs` the finding ids, units and launches it rests on |
| `units.md` | you | `\| unit \| pass \| state \| tree \| title \|` — a row per unit once its brief is drafted, state `drafted`; `ready` once every unit it is blocked by is committed; then written before every launch and command list: `implement · verify · debug · land · committed <sha> · blocked: <why>`; fix units are `f<k>`, numbers continue across passes |
| `units/<unit>/` | you, command lists | `brief.md`, `commit.txt`, `tests.log`, the unit's logs and patches, `created/` of a blocked unit |
| `launches.md`, `reports/<launch>.md` | `fsl.mjs save` | a row per launch; its final block, verbatim |
| `findings/<stage>.md` | you | the decision on every finding the stage's reports raise |
| `passes.md` | you, with `N` | `\| pass \| critical+major \| outcome \| why \|` |
| `surfaces/<name>.md` | you | a new surface's `SHAPE:` block |
| `shots/` | captures, fsloop-shots | `p<p>-baseline-<surface>.png`, `p<p>-final-<surface>.png`; init's `init-<name>.png` |
| `logs/` | command lists | every log that is not a unit's, `start-status.txt` |
| `gates.jsonl`, `run.json` | `fsl.mjs` | each gate's outcome; the run as one document |
| `report.md` | you, at Finish | the report file |

Every file you author in it is written with Edit/Write only, never `echo`, a heredoc or `node -e` in a shell string: a backtick in a journal row executes. Logs and patches are command output, redirected by the command that produces them.

**Stages** — the run is a sequence of stages: `p<p>-<step>` — `<p>` the pass, `1` without `N`; step `map`, `spike`, `decompose`, `units`, `review`, `fix`, then `verdict` without `N` or `assess` with it — then `integrate` and `finish`; `/fsloop init` has one, `init`. A stage is done when `node <start>/.claude/skills/fsloop/fsl.mjs gate <run folder> <stage>` prints `GATE <stage> green`, and the next starts only then; one exception — a red `gate integrate` whose every line ends `— it holds the push` is a held push, and Finish follows it (step 7). In a later pass, a step `assess.md` → Passes skips (Map, Spike) is never gated. Red lists what stands between the stage and done: settle each, gate again. Every gate checks the reports saved in its stage — a launch never saved is invisible to it — and every finding in them decided (Bar → Findings), and that the stage before it is green; what else it checks is named at its step.

**Launch records** — every launch's prompt opens with `Repo: <path>` and `Common: <run folder>/common.md`: the agents find the law, the role map and the project's facts there, a launch with no brief included. Its Agent `description` is its name within the stage, set when you launch it — `save` reads it from the transcript and the gates match on it: `<unit> <role>` (`u3 implement`, `u3 debug`, `f1 implement`, `u2 shape`, `u3 resolve`), `rebase resolve` (the pass-start rebase), `critic <lens>` (`critic code`, `critic craft`, `critic code verdict`), `craft <surface>` (Map's baseline, Assess — `<surface>` the slug Map gave it, the same at every stage: the report lines its scores up by it), `design check`, `spike <topic>`, `map`, `e2e`, `integrate fix`, `integrate debug`, `integrate resolve`, `prod check`, and init's `shots`, `shots proof`. Every launch of a run with a run id (all but `/fsloop spike`), on its completion, before you act on its report: `node <start>/.claude/skills/fsloop/fsl.mjs save <run folder> <stage> <agent id | output_file>`, `<stage>` the stage in progress — the next one you will gate; a transcript with no meta file takes its description as a last argument. It files the final block from the transcript Claude Code keeps to `reports/<launch>.md` and a row to `launches.md`, and prints the launch id, `<stage>-<description>` (`p1-review-critic-code`, `-2` on a repeat), the id finding ids use, and each `to judge:` line of the report with its id, `<launch>#judge-<n>`.

**Resume** — `/fsloop resume <run id>`: the run folder is the whole state — the last green gate in `gates.jsonl` is the stage done, `units.md` carries each open unit's state and lane, so a stopped session or a compaction loses nothing. Integrate is done when `logs/push.log.lines` shows the push at `exit 0`, or its gate held the push; a green `integrate` with no such line → Push. An init run with a green `init` gate and no `push` line at `exit 0` in `logs/land.log.lines` → its land list (`init.md` → Gate, land). A launch whose report never arrived: `fsl.mjs save <run folder> <stage> "<description>"` finds its transcript by its description among this run's launches — saved → that is its report; `no final message` or none found → relaunch, the lane's partial edits named. A unit found uncommitted in `<wt>` lands there before any lane opens. A run whose `common.md` says `Mode: inline` is not resumed: report its state — the files changed against `logs/start-status.txt`, the commits with its `Fsloop-Run` trailer, the last journal row — and stop.

## Bar

A finding is **above the bar** when it cites a rule: a done-criterion of the brief · a strict rule in `CLAUDE.md` or a rule file it names · a rule of the law (`law/`, under `law/ui.md` → Precedence) · an issue of impeccable's critique or audit (`fsloop-critic` lens 4), at the severity its P-level maps to · a line of `PRODUCT.md` · a claim in a spike doc the code contradicts · a codebase-design principle with a passed deletion test on a module the unit created or reshaped · an OPEN line of an implementer's or debugger's report · a debugger's `TEST: no correct seam` on a module the run created or reshaped — elsewhere a candidate for `mattpocock-skills:codebase-design`. A finding citing nothing is taste → candidates. An audit issue or any other generic checklist point the design law voids is dropped — not a candidate (`law/ui.md` → Precedence).

The product's own context binds the UI: `PRODUCT.md` (users, personality, anti-references) and `DESIGN.md` set the amount of interface, never taste — the brief's building blocks and reference set only the idiom. Every UI change goes through impeccable, unattended — `ui.md` names which launch runs which command. The measure is the new user's questions (`ux 0`), not the element count: an addition that closes a question is above the bar, one that closes none is noise.

**Declining.** A finding is declined by the user's words, or by you when it contradicts a finding an earlier assessment or review raised (the run does not ping-pong) or argues against a settled decision; "pre-existing", "backend", "frontend", "later", "new functionality" are never reasons — a unit is a vertical slice. A declined finding is decided `declined`, its why a journal row; it never becomes settled and never counts toward stall.

**Reversals.** A finding that asks to undo a fix of this run is above the bar only when it cites a rule that fix broke; otherwise a candidate. Every reversal taken is a journal row, `refs` both findings — the report's decisions list it.

**Findings** — a finding's id is `<launch>#<id>` (`p1-review-critic-code#code-3`), the one every brief, trailer, verdict prompt and journal row uses. Each FINDINGS line of a stage's reports gets one row in `findings/<stage>.md`, `| finding | decision | ref | repeat | why |`, the decision one of:
- `fix` — taken; ref the unit that takes it once one is drafted (`—` before), at Assess the next pass, `p<p+1>`. A unit takes it by naming it under its brief's `## Closes`;
- `candidate` — below the bar, or past what the run may take;
- `dropped` — against a settled decision, ref its journal row; or voided by the law, ref the rule that voids it;
- `declined` — Bar → Declining, ref the journal row or the finding it contradicts;
- `duplicate` — one cause another finding names, ref that finding;
- `open` — above the bar and not taken: the run stops at this pass, or it needs what `.spike/` lacks.

`repeat` names an earlier `fix` finding this one shows still standing, else `—`; `why` is the rule and the reason, one line. A finding no report raised — a red suite line, a failed end-to-end step — is the run's own: its id `<stage>-own#<n>`, its severity in a `severity` column.

## Loop

The run is one pass: the plan built unit by unit (steps 1–4), one Review of everything built (step 5), one Fix of what Review found above the bar (step 6), Integrate. Each finding is reviewed once — a fixed finding once more, by its verdict: what Fix leaves open goes to the report as open, by id. `N` given → `assess.md` runs between Fix and Integrate and decides whether another pass is built.

1. **Map.** One `Explore` (`model: sonnet`) returns tables, no prose, no code excerpts: areas the goal touches (files, pattern in use; a UI area's **building blocks** — the shared components, hooks and layout primitives it would use, with paths, the reference the project's UI rules name for its kind, if any, and the shot fixture that shapes its page — for a new surface, the nearest existing route by task; a backend area's reference candidate with path; every consumer of a shared file the goal will change, by `git grep -l` of its import); one line per surface the goal reshapes with its **production shape** — counts and a typical row through the production-shape role, never a dev database; a surface or table production lacks takes its shape from the production rows it is built over and, for data production does not hold yet, the product's stated volume against the schema; and the **unknowns** — every external system, protocol, format or behaviour the goal depends on, each with the doc that covers it (`docs/api/*.md`, `docs/research/*.md`, `docs/*.md`, `.spike/toolkits/*/README.md`) and what that doc leaves `unverified`, or `none`. A shape with no source is a decision, not a guess. Then every reshaped surface gets its baseline (`ui.md` → Baseline). Done when every UI area has its building blocks and every backend area a reference, every reshaped surface its production shape and its baseline, every unknown a doc or `none`, and `gate p<p>-map` is green — every baseline finding decided.

2. **Spike.** Every unknown with no doc, or whose doc leaves unverified what a unit will call, gets a `spike-researcher` launch per `spike.md` — framed from Map's line, independent ones in one message, at most `K`, each in `<wt>` with its sessions acquired before and released after; its ANSWERED, UNVERIFIED and OPEN lines are classed as `spike.md` → Verify says. Its doc lands uncommitted in `<wt>/docs/`: before any lane opens, one command list commits the spikes' docs on `fsl/<run id>` (`git add` by path, `git commit -F` a message per `Commit message`), so every lane branches with them. Nothing unknown → the step is one journal row. Done when `gate p<p>-spike` is green.

3. **Decompose.** Tracer bullets: each unit a vertical slice through every layer it needs, verifiable and committable alone; a prefactor that makes the slices easy — a change to a shared file that several slices then build on — is its own first unit; a wide refactor — a rename or retype whose call sites no slice can carry green — runs expand–contract: the new form beside the old, then migrate batches by directory each blocked by the expand, then the contract blocked by every batch — except the key-merged catalogs and the append-only registries, where each unit writes its own lines. A unit is sized by the files it writes, not by the goal's list: each one pays a lane, an install, a fresh implementer reading `common.md` and its brief, a Verify and a Land, and two units sharing a path never run at once (Lanes) — so goal items whose manifests share a file other than those catalogs, or that chain by `Blocked by` through one area, are one unit; an item whose whole change is a test, a doc or one small file joins the unit that writes its files or works on its page, and stands alone only when no unit does, a decision. The ceiling: one surface per unit, so its commit says one thing, and a manifest one implementer carries red → green in one launch. Each unit's **kind** comes from its manifest, by role: a UI part is a page, component, style or user-facing string; a backend part is anything that runs on the server — server actions, data loaders, route handlers, services, workers, schema and migrations. `ui` has only the first, `backend` only the second, `full` both — most units are `full`. A unit that makes a new surface is shaped before its brief (`ui.md` → A new surface). Each brief `units/u<k>/brief.md` opens with `Kind: ui|backend|full` (with `+ table` when its UI part holds or will hold a data table) and `Blocked by: u<k>, …` (or `—`), then seven sections under these headings, in this order — a section with nothing to say holds `—`, except Problem, Done-criteria and Files:
   - `## Problem` — the problem in the user's words, the defects observed (a reshaped surface's baseline craft findings at critical or major, verbatim) and the spike facts it rests on — never the solution: the shape of the fix belongs to the implementer, a preference of yours goes in marked as a suggestion; an «already does this» claim carries the `file:line` that does it — no line, no claim;
   - `## Seams` — a backend part's interfaces the tests hit (`—` only with `Kind: ui`), named: a service function, a handler called directly with a job row, an action, a client method against a fake transport; a test past a seam is a finding;
   - `## Done-criteria` — each a command: a backend part's first is the red test at the seam (`<test, one file> <file>`) that must go red before the code and green after; a live criterion names its `.spike/` session or sample and its command, per `backend.md`; a parser, codec or format reader's names its known-answer sample — from an external implementation or a real file under `.spike/data/` (`tests` → Shape); a UI part's criteria name the production shape the surface must read well at and a form's task walk, each proven by a test — its look is judged on the final frame at Review;
   - `## Files` — the file manifest, naming the shared catalogs it may write — a unit that grows a registry names its guard's files as additive edits, never «not touched»; never `CLAUDE.md`, `.claude/` or settings — yours alone; a new surface's manifest names its shot fixture (`ui.md` → The shot server) at the production shape's volume, so its final frame has data;
   - `## Reference` — a UI part's building blocks from Map, region by region, and the reference the project's UI rules name for its kind where they name one; a backend part's best in-repo example of the same kind (a handler for a handler); the blocks and the reference set the idiom, `PRODUCT.md` and the UI rules the amount; where a block or reference breaks a rule, the rule wins and the brief names the gap as a defect to leave behind; a new surface's brief cites its `surfaces/<name>.md`;
   - `## Settled` — settled decisions: the user's words, interfaces committed units expose, spike facts — each with why; nothing else is settled;
   - `## Closes` — the ids of the findings decided `fix` that this unit takes: Map's baseline, the design check's, a previous Assess's.

   A brief is **whole** when it has `Kind:`, `Blocked by:` and these seven sections.

   Units cover the goal as asked. An open-ended clause in the goal ("the rest by the bar") admits only what the bar rates critical or major; debt noticed along the way goes to **candidates**, never into a unit. Each unit gets its `units.md` row. Done when the journal holds each surface's fixture when any unit has a UI part (`ui.md` → The shot server), with two or more UI units the briefs passed the design check (`ui.md` → Design check), and `gate p<p>-decompose` is green: every brief whole, every `fix` finding of Map, the design check and the previous Assess under some brief's `## Closes`.

4. **Units, in lanes.** At pass start, no lane open: `git fetch origin`; `git -C <wt> merge-base --is-ancestor origin/<default> fsl/<run id>` true → nothing to rebase; otherwise a command list for `git -C <wt> $MJ rebase origin/<default>` on the run branch — a conflict → Resolve.
   - **Implement.** `fsloop-implement` with `Repo: <lane>` and the brief's path — never the brief's text. Its report carries RED before GREEN for a backend part; CREATED extends the manifest. A CREATED path another open unit names or created is recorded; the second to land meets it in Resolve.
   - **Verify.** One command list in the lane, each command with its expected outcome — live criteria in it make it a background one (Background commands): the RED command (green now); the unit tests; the lint; the type-check, unless the last launch that edited the unit was an `fsloop-implement` whose `tests.log` beside its brief has its last `type-check exit` line at `exit 0` and no file of the unit is newer than that log (`find <files> -newer <log>` prints nothing) — then that log is its evidence, copied into the start checkout's `units/<unit>/` when the unit runs in a lane (after an `fsloop-debug` FIX it always runs here); every other done-criterion command, live ones under `LIVE=1`; schema changed → the migration generate and `ls` of the migration file. Red → its log path, the red line verbatim, the brief path and `git diff` of the unit's files (a patch in its folder) to a fresh `fsloop-implement`, once. Still red → `fsloop-debug` with the exact red command, the brief path and the diff; it applies its own FIX, its LOOP command joins the done-criteria. Up to two debug launches per unit; then Block. A criterion blocked by missing infrastructure (no Docker, no env secret, a resource `.spike/` lacks) is a decision, the gate falls back to the offline criteria, the report says `unverified live` — never silently skipped.
   - **Land.** One lane at a time. Write `commit.txt` (Commit message), then one command list: `git status --porcelain` — a dirty file the unit did not touch is a stray: `git diff -- <file>` to a patch, `git checkout -- <file>`; `git add` by explicit path; `git commit -F <message>`; `git $MJ rebase fsl/<run id>` — a conflict stops the list → Resolve with `Repo: <lane>`; the base moved → type-check and the unit's tests again. Red → a fresh `fsloop-implement` with the red line and the brief's path, then — `git status` showing no rebase in progress — a command list for `git commit --amend --no-edit` with its files added by path, and the checks again. Green → `git -C <wt> merge --ff-only fsl/<run id>-u<k>`, close the lane; the unit is `committed <sha>`.
   - **Block.** Save `git -C <lane> diff` of the unit's files as a patch in its folder, record the exact state (`blocked: <why>` in `units.md`), close the lane. Units blocked by this one are blocked too, with the reason.

   The step is done when every unit of the pass is committed or blocked, every lane closed, and `gate p<p>-units` is green: each commit carries its `Fsloop-Run`, `Fsloop-Step` and `Fsloop-Closes`, each blocked unit its reason.

5. **Review.** Once, when every unit is committed or blocked and every lane is closed. First, when a unit has a UI part, the final capture (`ui.md` → Frames), done when `ls <run folder>/shots/p<p>-final-*.png` lists every surface it names, or the journal records why one has none. Then `fsloop-critic`, one launch per lens group in one message, `Repo: <wt>` — `LENS: code` always; `LENS: runtime` when a unit has a backend part, with the spike docs and every implementer's RED/GREEN lines; `LENS: craft` when a unit has a UI part, naming each surface a unit made or reshaped and each changed shared file's first consumer (`ui.md` → Frames), by its primary component file or route directory, with its final frame by path. Each carries the goal in the user's words, every committed unit's brief path, the run's file list (`git -C <wt> diff --name-only origin/<default>...HEAD`), settled decisions, Verify's `COMMANDS` lines and, as `to judge`, every `to judge:` line of the pass's implementers by its id (`p1-units-u3-implement#judge-1`; `save` prints it, `run.json` → `judges` lists them all) and each decision you left to Review — each to the lens whose rules it touches. Judge every finding against the bar in `findings/p<p>-review.md`: above it → `fix`, the fix list — a critical or major finding on a surface the run reshaped too, its file joining the fix manifest; taste, a minor in a file no unit touched, or a surface the run did not reshape → `candidate` — except a regression on a consumer of a shared file the run changed: above the bar, `fix`; the rest per Findings. Done when `gate p<p>-review` is green — every implementer's question has a JUDGED line opening with its id, or a journal row recording it open with the id in `refs` — and each decision you left to Review has a JUDGED line or a journal row; open ones go to the report as open and to no brief as settled.

6. **Fix.** The fix list — the review's `fix` findings —, once. Craft findings follow the craft critic's `ORDER:` — one unit `f<k>` per surface, its brief listing the surface's lines in sequence, each with its command (`/impeccable <command> <surface>`) and the finding ids it closes, verbatim; a line whose findings all fell below the bar or were dropped is skipped, recorded; `polish` last; manifest the surface's files plus the files its findings name; a craft finding whose cause is `component` or `token` goes to its cause group below instead, and the surface's unit is `Blocked by:` that group. The rest groups by cause, then by file: findings whose cause is `component` or `token` first — one group per shared file that removes them (the shared component, the theme, a lint contract), so the cause is fixed once, not per consumer; then the rest by file — findings sharing a file in one group, up to about ten a group; each group is a unit `f<k>` with a lane (`-f<k>` in place of `-u<k>`) and a brief `units/f<k>/brief.md` in the same shape: `Kind:` from its files, `Blocked by:` the cause group its findings' file consumes, or `—`; the problem = its findings verbatim, `## Closes` their ids; seams from the cited briefs, `—` only with `Kind: ui`; done-criteria = each finding closed, by the red test its rule asks for where a seam exists, plus the cited briefs' criteria on these files; manifest = the files the findings name — a fix that needs another file is re-decided `candidate` in `findings/p<p>-review.md`; reference and settled decisions from the cited briefs. Then step 4 for each group — Implement, Verify, Land — at most `K` lanes; each f-unit gets its `units.md` row and its finding rows their unit as ref. A finding still open after Verify and its debug goes to the report as open, by id. The fix is done when `gate p<p>-fix` is green: every `fix` finding under an f-brief's `## Closes`, every f-unit committed or blocked.

   **Verdicts** — stage `p<p>-verdict`, without `N` only (with `N` the pass goes to `assess.md` → Assess), when every fix unit has landed, in one message: `LENS: craft verdict` for all fixed surfaces, with their finding ids, the diff of every fix unit that took one of them — a cause group's included — as a patch and each surface's final frame; `LENS: code verdict` for every code and runtime finding in the fix list, with its line verbatim, the diff of the fix unit that took it as a patch and that unit's Verify `COMMANDS` lines — a green Verify proves the tests, not that a finding no test covers is gone. Each prompt names the findings by their ids, so each VERDICT line scores one, and carries each fix-unit implementer's `to judge:` id to the verdict whose lens it touches (with `N`, a journal row records it open). A finding scored `partial` or `unresolved` goes to the report as open, by id; a finding a verdict raises is judged by the bar in `findings/p<p>-verdict.md` — above it `open`, by id; below it `candidate`. Empty list → one journal row. Done when `gate p<p>-verdict` is green: every committed fix scored.

7. **Integrate.** A command list per phase (merge, checks), its log `logs/integrate-<phase>.log` — the phase with the build or the suite runs in the background (Background commands) — the git commands as listed and nothing beyond them. `git fetch origin`; `fsl/<run id>..origin/<default>` not empty → `git -C <wt> $MJ merge --no-commit origin/<default>`, then `git commit -F` a message per `Commit message` — one Resolve on final states, never a rebase of the run over it; the merge changed a file of a surface the run made or reshaped (`git -C <wt> diff --name-only HEAD^1 HEAD` against the units' manifests) → one `fsloop-critic` with `LENS: craft verdict` (`critic craft verdict`) on the fix patches and the merge's diff since the surface's final frame — a check like the others: each finding decided in `findings/integrate.md`, a critical or major one `fix` is a red line, fixed as below; after the fix of its findings the critic runs once more on the new diff, only its last report counts, and a critical or major finding that one raises is decided `open`. Then, merged or not: type-check, the build when build-exercised code changed, and — when the run is a large task (Project facts → suite) — the suite and the whole-repo lint (background, maximum timeout); otherwise each unit's Verify stands, a decision recorded. A red check line is work, not a finding, while Integrate can still fix it — except a `flaky` verdict in a file the run's diff does not touch that appears in a suite log older than the run's first commit: the run's own finding `integrate-own#<n>`, a candidate, with the evidence; a red time verdict first times two unchanged slow test files at the run's base and head under the lock — equal → the machine, both numbers recorded, no finding; a loaded machine's times never go to the baseline. Red → a fresh `fsloop-implement` (`integrate fix`) in `<wt>` with the red lines, its fix committed the same way (`Fsloop-Step: integrate`), the checks again; still red → `fsloop-debug` (`integrate debug`) as step 4, once, its fix committed the same way, the checks again; still red → each red line is the run's own finding `integrate-own#<n>` at major, decided `open`. Then `gate integrate`: it names every critical or major finding not closed (of a review, a verdict, the merge's last critic, or the run's own at Integrate): one the run left `open` ends `— it holds the push`, any other `— settle it before the push`. Green → Push. Red → settle every line that does not end so, gate again; once only held findings remain, each is listed by id in the report, the verdict says the goal is not met, no push; the report names `fsl/<run id>` and `<wt>`, both kept; Finish. Push: its own command list (`logs/push.log`), after the `git log origin/<default>..fsl/<run id>` list you approved — `git -C <wt> push origin fsl/<run id>:<default>`; rejected → `origin` moved: fetch, the same merge, push once more; rejected again → reported verbatim, never forced. A project whose `CLAUDE.md` forbids an agent's push to `<default>` gets `git -C <wt> push origin fsl/<run id>` instead, and the report names the branch to merge. Success → the shot teardown in `<wt>` when it raised a shot database, `spike-lease.mjs unlink <wt>` and, only after it printed `unlinked` or `nothing linked` and `<wt>/.spike` is gone, `git fetch origin`, `git merge-base --is-ancestor fsl/<run id> origin/<default>` → `git worktree remove --force <wt>` and `git branch -D fsl/<run id>`; otherwise both stay; before Finish `spike-lease.mjs status` names no holder under `<repo parent>/fsl/<run id>` — another run's lease is not this run's to free.

8. **Finish** — first the run's leftovers: the shot teardown in every tree of the run still on disk that raised a shot database, `<db>_e2e_<run id>` dropped; in the worktree mode the start checkout brought onto `origin/<default>` when it sits on it with no commits of its own — `git $MJ pull --rebase --autostash origin <default>` there, after the check of `inline.md` → Before every pull for a git operation in progress; otherwise it is left as it is. A run that pushed to `<default>` then checks the deploy when the project has a production-shape role: `prod-check` (description `prod check`) with `Repo:` the start checkout, the expected sha — `origin/<default>` right after the push — and what the deploy should add: the run's migrations by file name, its crons, tables and settings, from the briefs. Its `VERDICT` line and anomalies go into the summary and the report; `degraded` or `failed` → the goal is not met, whatever the review says. Then two deliverables, both in the user's language. **Report file** `report.md` in the run folder, run id first, then tables only. Yours, from what no file holds: spikes (question / doc / answered / unverified / what `.spike/` lacked) · evidence (criterion / command / outcome, `unverified live` marked) · deploy (sha / verdict / anomalies) · spend, the verbatim output of `node <start>/.claude/skills/fsloop/spend.mjs <session id> --shots <run folder>/shots` (the session id is the folder name in your scratchpad path). Then `node <start>/.claude/skills/fsloop/fsl.mjs report <run folder>` writes the rest from the run folder — decisions, units, every finding with its status, the questions to judge, candidates, each surface's scores, and with `N` the passes — regenerated in place, never edited by hand. Then `gate finish`: green closes the run in `run.json`; red → settle it before the summary. **Chat summary** opens with a block for a reader who does not read code — plain language, none of the run's vocabulary (unit, finding, lane, sha, `unverified live`, candidate): whether the goal is met and whether it is live, from the deploy check; what changed as the user meets it, each page by its navigation label and its address; each changed surface's final frame embedded as an image by absolute path (`![<surface>](<path>)`) — taken before the fixes, so one sentence names what the fixes changed on it; what to check by hand on the live site — the task's steps; what is not done and what the run needs from the user (a resource for `.spike/`, a code, money), one sentence each. Then the technical part: verdict — goal met in full or not, with the review's open findings counted (with `N`: converged, stalled or cap per `assess.md`); what runs for real and what is `unverified live`; run id; units / commits / blocked. Then what was built · commit table (sha / what, after the merge) · integration result · checks, each named by what it verifies · spend: the last line `spend.mjs` prints, verbatim — its context total is the agents panel's Σ · not done, by kind: scope not taken / open after Fix / debt found · what to drop into `.spike/` · the report file as a link.
